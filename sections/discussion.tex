\section{Discussion}

\subsection{Interpretation of Results}
The primary finding is that combining multiple data sources and forecasting methods produces more reliable guidance than relying on any single approach. When signals from search trends, review sentiment, and usage patterns were combined, predictions demonstrated improved robustness across different feature types. Some features respond to short-term interest cycles while others follow steadier long-term trajectories—the ensemble methodology addressed both patterns effectively.

The visualization component also demonstrated substantial value. Presenting stakeholders with the sources of predictions and confidence levels reduced the perception of the system as opaque. Decision-makers expressed greater willingness to act on forecasts when the underlying reasoning was transparent.

\subsection{Limitations Encountered}
Several limitations were encountered during this research.

\textbf{Data source heterogeneity} presented challenges. Google Trends provides monthly aggregates, app reviews include precise timestamps, and metadata exhibited gaps throughout. Temporal alignment at monthly intervals required more effort than initially anticipated.

\textbf{Feature behavioral variation} necessitated flexibility. Some features exhibited clear seasonal patterns while others trended steadily. No single model proved universally optimal—different features required different analytical treatment.

\textbf{Time constraints} limited thoroughness. Additional cycles for hyperparameter tuning and load testing would have been beneficial, but project timelines imposed constraints.

\subsection{Mitigation Strategies}
When challenges arose, adaptive strategies were employed.

For data alignment issues, careful preprocessing steps were developed and all assumptions were documented to ensure transparency for code reviewers. Rather than attempting to identify a single optimal model, the ensemble approach was adopted with validation performance guiding model weight allocation. Given limited testing time, correctness and reproducibility were prioritized over exhaustive performance benchmarking. A system that reliably produces accurate results was preferred over one optimized for speed but prone to errors.

\subsection{Lessons Learned}
Several lessons emerged from this work. First, establishing clear data contracts early prevents substantial integration difficulties—when all components agree on input and output specifications, integration proceeds more smoothly. Second, modular system construction facilitated model substitution without requiring comprehensive refactoring. Third, implementing tests from the beginning rather than retrofitting them at project completion caught problems before they compounded.
