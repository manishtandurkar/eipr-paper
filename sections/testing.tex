\section{Testing and Evaluation}

\subsection{Testing Methodology}
Testing was integrated throughout the development process at multiple levels, from individual functions to complete end-to-end workflows.

\textbf{Unit tests} verify correctness at the smallest scale. Every data cleaning function, feature extraction routine, and model wrapper includes tests confirming specified behavior. The pytest framework was selected for its simplicity and broad support.

\textbf{Integration tests} verify that components function correctly together. The preprocessing pipeline feeds into model training, which feeds into API endpoints—these handoffs are tested to ensure data integrity throughout the pipeline.

\textbf{End-to-end smoke tests} traverse the entire workflow from raw data ingestion through chart rendering in the browser. While not exhaustive, these tests detect obvious failures before deployment.

\textbf{Load tests} provide performance characterization, confirming that the API responds within acceptable time limits and maintains stability under moderate traffic.

\textbf{Regression tests} execute automatically on code changes. If modifications inadvertently affect model behavior or API contracts, tests detect the change before integration.

\subsection{Test Coverage}
The test suite addresses multiple scenarios including feeding malformed records to the data ingestion module—missing fields, invalid timestamps, unexpected characters—to verify graceful error handling. Natural language processing feature extraction is tested on edge cases including very short reviews, reviews containing emoji, and occasional non-English content. Model serialization and deserialization is tested by training a model, saving it to disk, loading it, and verifying consistent predictions. API response testing confirms that returned JSON structures match frontend expectations, including appropriate error messages. Dashboard rendering is tested with no data, large datasets, and multiple overlapping series to verify UI robustness under varying conditions.

\subsection{Evaluation Metrics}
Multiple metric categories are tracked for comprehensive evaluation.

For \textbf{forecasting models}, Mean Absolute Error quantifies typical prediction deviation, Root Mean Squared Error applies greater penalty to larger errors, and Mean Absolute Percentage Error enables cross-feature comparison at different scales. Holdout validation and rolling-origin testing provide honest estimates of performance on future data.

For the \textbf{system overall}, API response times (specifically 95th percentile), success rates, and memory usage during model inference are monitored.

For \textbf{code quality}, test coverage on critical modules is tracked along with the count of bugs detected by the CI pipeline before production deployment.

\subsection{Continuous Integration}
Every pull request triggers the complete test suite through GitHub Actions. Unit tests, integration tests, and model validation steps execute automatically. If model validation fails—indicating that a code change unexpectedly degraded prediction accuracy—the pull request cannot be merged without explicit reviewer approval. This process maintains main branch stability and reliability.

\subsection{Testing Results}
Comprehensive coverage was achieved across the core pipeline. Unit tests cover data processing and model components, integration tests verify API contracts, and smoke tests confirm correct frontend rendering. Priority was given to reproducibility and reliability over exhaustive edge case coverage. For a research prototype, this represents an appropriate tradeoff between thoroughness and development velocity.
