\section{Methodology}
This section describes the methods used for data collection, preprocessing, modeling, and evaluation.

\subsection{Data Collection}
Data sources include Google Trends time-series, curated review datasets from Kaggle, and app metadata. Collection scripts normalize timestamps and align signals to a monthly cadence. Data collection handles rate limits, retries, and logging to ensure reproducibility.

\subsection{Preprocessing}
Preprocessing includes:
\begin{itemize}
\item Cleaning and deduplication of records.
\item Missing value handling via interpolation or forward-filling where appropriate.
\item Outlier detection and filtering using statistical thresholds.
\item NLP-based feature extraction from review text to produce mention counts and sentiment scores.
\end{itemize}

\subsection{Modeling Approach}
We implement three complementary forecasting approaches: Exponential Smoothing for short-term responsiveness, ARIMA for modeling seasonality and autoregressive structure, and Linear Regression to incorporate external covariates. Models are trained on historical windows with a holdout period for evaluation. An ensemble approach combines model forecasts using weights derived from historical validation performance.

\subsection{Evaluation Protocol}
Model evaluation uses a train/validation/test split with rolling-origin evaluation where feasible for time-series validation. Standard forecasting metrics used include Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), and Mean Absolute Percentage Error (MAPE). Confidence intervals are estimated where supported by the model to provide uncertainty quantification.

\subsection{Backend Implementation Details}
Backend implementation choices were driven by reproducibility and ease of integration. Scripts are organized into modules for ingestion, preprocessing, training, and serving. Artifacts are versioned with metadata describing data windows and hyperparameters. API design favors small, well-documented endpoints returning immutable forecast artifacts.

\subsection{Reproducibility}
All data transformation steps and model training scripts are documented and included in the repository. Example notebooks demonstrate how to reproduce key experiments, retrain models on updated data, and regenerate the figures used in the paper.
